This release fixes promotion of immutable GitHub Releases.

- Publish and verify the retained candidate distributions on PyPI while the final GitHub Release
  remains a draft.
- Attach durable verification evidence and seal `release-manifest-v1.json` before publishing GitHub.
- Require the producer's exact sealed-manifest SHA-256 during finalization and verify the published
  release without further asset uploads.
- Retain the v1 manifest format. Newly sealed draft snapshots use the stable Release creation
  timestamp; older published snapshots retain their publication-timestamp semantics. Manifest
  consumers must account for the recorded draft snapshot when checking a published Release.
- Reuse identical sealed manifests on reruns and reject attempts to repair locked Releases by upload.
- Model immutable release assets and tags in the local harness, with regression coverage for
  publication order, digest gates, snapshot validation, and recovery.

The previously published `0.1.2` GitHub Release and PyPI distributions are preserved. Its missing
final manifest and evidence cannot be attached to the already-immutable Release; this fix applies
the corrected lifecycle to subsequent releases.
